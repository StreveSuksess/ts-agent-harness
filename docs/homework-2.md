Учебный агент для отчётов по трекеру, продолжение первой домашней работы. Заявленный уровень — **10 из 10**, итог выставляется вручную.

Для сдачи нужны доступный репозиторий, заявленный уровень, воспроизводимые команды, зафиксированные конфигурации, сценарии и программные проверки вне рабочей области агента, логи всех реальных trials, сводка и вывод по гипотезе, пример доктора, версии маркета, результаты проверки обновления и скриншоты. Итоговый балл выставляет преподаватель.

## Подключение моделей

Для **проверки сданных результатов** достаточно Node.js 22.13+ и зависимостей проекта.

```sh
npm ci
npm run eval -- verify ab
npm run eval -- verify update
./agent ui
```

Для **живого диалога** нужны два локальных процесса. Их можно оставить работающими между запусками CLI и Студии.

1. **Laya.** Подготовьте мультиязычный чекпойнт, запустите сервер и дождитесь `"loaded":["multilingual"]` в ответе на `curl -fsS http://127.0.0.1:18000/health`. Команды установки из публичных исходников, ревизия весов и отдельный пример запроса приведены в [руководстве](extensions.md).
2. **Ollama.** Посмотрите `ollama list`. Если сервис остановлен, запустите `ollama serve` в отдельном терминале. Если подходящей модели ещё нет, выполните `ollama pull qwen3:4b`. Скопируйте `.env.example` в `.env` и задайте `OPENAI_MODEL` равным имени из списка. Для работы с трекером оба адреса должны вести на loopback. [Qwen3 в Ollama](https://ollama.com/library/qwen3).
3. Откройте `./agent` в терминале или `./agent ui` и указанный в консоли адрес. План и отдельные записи в режиме Safe ожидают вашего решения. Примеры двух последовательных промптов приведены в [README](../README.md#попробовать-трекер).

Сохранённые серии работали с Laya multilingual из локальной ревизии `0960545a2eedadb4dec1d22548cda6efee887249`. Те же веса отдельно проверены с публичной Laya 0.3.7. Реальные запросы и ответы этой сборки сохранены в [примере Laya](../evidence/laya-local.json).

Для генерации в сохранённых измерениях использовался локальный импорт Qwen3 4B Q4_K_M под именем `harness-qwen3:4b-local`, Ollama на CPU, контекст 8192. SHA-256 файла GGUF — `c5456ef082665fac2cf461f8d15799a2b814e35ff811195177adf762a9a48160`. Digest модели Ollama, точные параметры генерации и хеши входных файлов зафиксированы в [манифесте A/B](../evidence/ab/manifest.json). Публичный тег подходит для собственного повторения. Другая сборка весов, шаблон чата и семплирование могут изменить результат. Для воспроизведения логики проверки на сданных данных используйте команды `verify`.

## Разбор одного запроса

Возьмём первый B-запуск сценария `open`. В нём видно, **кто именно делал каждый выбор**. [Исходный журнал](../evidence/ab/trials/open-B1/events.jsonl).

1. `StudioSessions.start` или `executeTrial` создаёт run с отдельным ID. Харнесс находит `SKILL.md`, читает конфигурацию доверенных MCP-серверов, делает `initialize` и `tools/list`. Состояние хранит закреплённые версии. [Создание снимка](../src/extensions/index.ts).
2. До первого вызова Qwen харнесс отправляет локальной Laya `POST /v1/systemone`. В теле — текст запроса, контекст недавних реплик при наличии, имена и описания кандидатов. У каждого вопроса есть вариант `none`. В журнале B1 событие `laya_route` содержит `skill=open-tasks` и `mcp=mcp_tracker_list`. [Формирование запроса](../src/studio/laya.ts) · [порядок вызовов](../src/runtime/model-turn.ts).
3. Харнесс ставит два вызова в очередь. `load_skill` возвращает полный текст выбранного скилла, `mcp_tracker_list` делает `tools/call` к отдельному процессу. Разрешения, схема, лимиты и выбор Laya проверяются до исполнения. Для MCP с обязательными аргументами имя закрепляет Laya, а значения аргументов формирует генератор. [Проверка выбора](../src/runtime/extension-tools.ts) · [исполнение](../src/runtime/call-execution.ts).
4. Qwen видит результаты вызовов, предлагает `write_file`; runtime пишет `answer.json` в workspace. Затем Qwen вызывает `complete_task` с ID доказательства. В этой попытке файл содержал три открытых ID из фикстуры. Во внешней проверке порядок ID не влияет на результат. [Файл ответа](../evidence/ab/trials/open-B1/answer.json) · [критерии](../src/evals/cases.ts).
5. CLI и UI читают события с `session_id`, `run_id`, временем, типом и данными. `tool_call` показывает аргументы, `tool_result` — результат, `skill_loaded` подтверждает фактическую загрузку. `decision` хранит решение пользователя. В отчёте раздельно указаны входные и выходные токены Laya и генератора, а также полнота данных. Служебный анализ доктора выполняется правилами и расходует 0 токенов. [Учёт событий](../src/studio/events.ts) · [статистика](../src/studio/stats.ts) · [правила доктора](../src/studio/doctor.ts).

Если Laya вернула `none`, инструмент остаётся недоступным этой реплике. Неизвестное имя, несовместимый ответ и недоступность Laya блокируют запуск с причиной в журнале. После восстановления сервиса его можно продолжить командой `/resume`.
