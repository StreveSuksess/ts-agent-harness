# Как добавить навык, подключить источник данных и проверить обновление

В учебном трекере участвуют две локальные модели. Laya получает запрос пользователя и **описания** доступных навыков и инструментов. Она выбирает нужные имена или `none`. Харнесс проверяет выбор по политике и схеме аргументов. Генеративная модель получает результат чтения навыка или ответа трекера, затем работает с файлами сессии. Конкретный выбор Laya, фактический вызов и ответ инструмента видны как отдельные события запуска.

## Запуск Laya с готовыми весами

Понадобятся Python 3.12, `uv`, исходники Laya и мультиязычный чекпойнт. Если исходники и виртуальное окружение уже подготовлены, запустите из корня проекта:

```sh
LAYA_CHECKOUT=/absolute/path/to/laya \
LAYA_MULTILINGUAL_MODEL_PATH=/absolute/path/to/multilingual \
./scripts/laya-local.sh
```

Скрипт по умолчанию использует `.agent/laya-env/bin/python`, два потока CPU и порт 18000. Их можно задать через `LAYA_PYTHON`, `LAYA_CPU_THREADS` и `LAYA_PORT`. Сервер слушает только `127.0.0.1`. Он загружает указанный локальный чекпойнт с `HF_HUB_OFFLINE=1`. Первое чтение весов занимает время. Готовность показывает команда `curl -fsS http://127.0.0.1:18000/health`: в `loaded` должно быть `multilingual`. При смене порта задайте приложению `LAYA_BASE_URL=http://127.0.0.1:<порт>`.

### Подготовка из публичных исходников

Команды ниже рассчитаны на пустые каталоги в `.agent`. Для этой сборки проверены upstream Laya 0.3.7, Python 3.12 на macOS arm64 и публичные веса размером около 644 МБ. [Исходники Laya](https://github.com/NandhaKishorM/laya/commit/010bacef009c855ccba814b51f7c8e1d38ab5e3f) · [Ревизия весов на Hugging Face](https://huggingface.co/convaiinnovations/laya/tree/c56c1b6f535b746ed1709b8cc65941c9d7991f00/multilingual).

```sh
mkdir -p .agent
git clone https://github.com/NandhaKishorM/laya.git .agent/laya-src
git -C .agent/laya-src checkout --detach 010bacef009c855ccba814b51f7c8e1d38ab5e3f

uv venv --python 3.12 .agent/laya-env
uv pip install --python .agent/laya-env/bin/python \
  'torch==2.15.0' 'transformers==4.57.6' 'safetensors==0.8.0' \
  'huggingface_hub==0.36.2' 'numpy==2.5.5' 'pydantic==2.14.4' \
  'fastapi==0.165.0' 'uvicorn==0.54.0'

.agent/laya-env/bin/python - <<'PY'
from huggingface_hub import snapshot_download

snapshot_download(
    'convaiinnovations/laya',
    revision='c56c1b6f535b746ed1709b8cc65941c9d7991f00',
    allow_patterns='multilingual/*',
    local_dir='.agent/laya-weights',
)
PY
shasum -a 256 .agent/laya-weights/multilingual/model.safetensors

LAYA_CHECKOUT="$PWD/.agent/laya-src" \
LAYA_MULTILINGUAL_MODEL_PATH="$PWD/.agent/laya-weights/multilingual" \
./scripts/laya-local.sh
```

Ожидаемый SHA-256 файла весов — `9d628fd971b700382ac6f65920a86f149777b2e748e0c955fb3b19695aa8f204`. В репозитории сохранены два настоящих запроса к этой версии Laya, её выбор и счётчики токенов. В первом примере модель выбрала навык, но пропустила MCP. Во втором определила оба имени. Чтобы повторить второй запрос на работающем сервере, выполните:

```sh
node --input-type=module -e "
import {readFileSync} from 'node:fs';
const {examples} = JSON.parse(readFileSync('evidence/laya-local.json','utf8'));
const result = await fetch('http://127.0.0.1:18000/v1/systemone', {
  method: 'POST', headers: {'Content-Type': 'application/json'},
  body: JSON.stringify(examples[1].request)
});
console.log(await result.json());"
```

## Навык из локальной папки

Для нового навыка создайте `skills/<имя>/SKILL.md`. Имя в YAML и имя папки должны совпадать. Поддерживаются строчные латинские буквы, цифры и разделяющие слова дефисы. Описание до 1024 символов сообщает маршрутизатору, при каком запросе применять инструкцию. Пример:

```markdown
---
name: priority-report
description: Prepare a report of tracker tasks grouped by priority.
---
Прочитай указанный пользователем источник задач. Сгруппируй задачи по приоритету.
Если у строки отсутствует приоритет, добавь её в отдельную группу и укажи это в отчёте.
```

При старте run харнесс читает локальные пакеты, проверяет YAML и вычисляет SHA-256. Ошибка отдельного пакета попадает в диагностику. Другие навыки остаются доступными. Для выбранного пакета `load_skill({"name":"priority-report"})` возвращает полный текст и версию из снимка запуска. Включение и отключение в UI действует для следующих запусков. [Формат Agent Skills](https://agentskills.io/specification).

## Ещё один MCP-сервер

`configs/mcp.json` — список разрешённых администратором программ. В репозитории настроен `tracker`. Он получает зафиксированные данные из `configs/tracker.json`, экспортирует метод `list` и выводит в stdout по одному JSON-RPC сообщению на строку. Его можно проверить на ошибке в модульном тесте или в сценарии `outage`. В последнем сервер возвращает MCP-ответ с `isError: true`.

Чтобы добавить совместимый Node.js stdio-сервер, положите его за пределами рабочей области модели и добавьте в `servers` запись:

```json
{
  "study": {
    "command": "node",
    "entry": "mcp-server/tracker.mjs",
    "args": [],
    "allowRead": [],
    "readOnlyTools": ["list"],
    "timeoutMs": 4000
  }
}
```

Имя инструмента получится `mcp_study_list`. Для доступа из Студии разрешите его также в `extensions.allow` файла `configs/studio-policy.json`, затем включите сервер в настройках. Внешний сервер получает только явно разрешённые файлы и заявленные администратором методы чтения. Специально для сервера с именем `tracker` хост передаёт снимок задач в `TRACKER_DATA`. Каждый stdio-процесс стартует в отдельной временной папке. Для зависимости из своей файловой системы добавьте нужный путь в `allowRead`. Относительные пути разрешаются от файла конфигурации.

Клиент выполняет `initialize`, `notifications/initialized` и `tools/list`, проверяет JSON Schema и вызывает `tools/call`. Перед вызовом он повторно проверяет текущую конфигурацию, хеш входного файла сервера и список разрешённых методов. Поддерживаются версии MCP `2025-03-26` и `2024-11-05`, аргументы-объекты и текстовые результаты. Таймаут ограничивает всё соединение, stdout ограничен 512 КиБ. Разрешения Node ограничивают чтение и запись файлов и запуск процессов. Доверие к установленному серверу остаётся необходимым, в частности для его сетевого поведения. [Транспорт stdio](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports) · [Схемы tools и обработка ошибок](https://modelcontextprotocol.io/specification/2025-03-26/server/tools).

## Маркет и обновления

Локальный источник `study-market` имеет две воспроизводимые ревизии в `market/v1` и `market/v2`. Каждая содержит индекс с именем, описанием, версией, путём `<имя>/SKILL.md` и SHA-256 полного содержимого. Реестр хранит инструкции в Markdown. Установка проверяет размер, расположение, целостность, YAML и совпадение описания с индексом.

1. Откройте маркет в Студии и проверьте `v1`. Предустановлен `open-tasks@1.0.0`. Появится предложение `handoff-note`.
2. Попросите агента подготовить передачу смены. Маршрутизатор увидит описание предложения. Установка требует подтверждения, в том числе в автоматическом режиме. Новый навык доступен следующему запуску. Найденное предложение, установка и чтение инструкции различимы в истории.
3. Выберите источник ревизии `v2` и запустите проверку. Появятся новый `stale-items` и кандидат `open-tasks@2.0.0`. Пока сравнение не завершено, текущая установленная версия остаётся активной.
4. Запустите сравнение в UI или включите авточек и автообновление. Студия проверяет источник при старте, смене настроек и получении нового запроса. В авторежиме кандидат проходит тот же эксперимент. В момент принятия решения заново сверяются хеш активной версии и хеш кандидата.
5. При положительном решении новая версия применяется к будущим запускам. Снимок уже начатого запуска, в том числе после возобновления, хранит исходный текст навыка. Кнопка отката возвращает предыдущую версию. Отвергнутая и откаченная версии больше не предлагаются автоматически с тем же хешем.

Состояние и журнал находятся в `.agent/extensions/market.sqlite`, проверенные пакеты — в `.agent/extensions/packages/<sha256>/<имя>/SKILL.md`. Фоновые события содержат время, уникальный ID, источник, действие, причину и хеши версий, когда это применимо. Их поля `run_id` и `session_id` равны `null`. Действия инструмента внутри run отдельно отражены в его трассе.

Чтобы воспроизвести поиск и установку через настоящий агентский цикл, сначала запустите локальные модели, затем выполните:

```sh
npm run build
node --env-file-if-exists=.env scripts/market-agent-demo.mjs .agent/replay-agent-install
```

Сценарий создаёт временный маркет и отдельную рабочую папку. Laya выбирает навык, харнесс ищет предложение, а генератор решает, вызвать ли установку. Скрипт выполняет роль оператора и подтверждает только установку `handoff-note` и запись в указанный пользователем файл. При успешной установке второй запрос использует новую версию каталога. В `summary.json` и файлах `<run_id>.jsonl` сохраняются фактические решения.

Повторить установку, обновление и измерение в отдельном временном маркете можно в корне проекта с запущенными локальными Laya и генеративной моделью:

```sh
npm run eval -- update --out .agent/replay-market
npm run eval -- verify update --out .agent/replay-market
```

В `market-review.json` будут версии и хеши до и после решения, названия обнаруженных навыков и журнал событий. В `summary.json` и `trials.jsonl` — результат gate и наблюдения по всем 30 попыткам. Отдельные тесты с управляемым результатом проверки покрывают ветви принятия, отказа, откат, конкурентное сравнение и испорченный каталог.

```sh
npm run build
node --test dist/tests/extensions.test.js dist/tests/extension-boundaries.test.js
```
