# Протокол измерения

Гипотеза до запусков: инструкции по отбору открытых задач и подсчёту по владельцам улучшат долю правильных файлов в соответствующих сценариях. Загрузка инструкций может повысить расход токенов. Контрольная задача не требует скилла. В каждой конфигурации учитываются все попытки.

| Сценарий | Замороженные данные | Что проверяем в answer.json | Маршрут B, old и new |
|---|---|---|---|
| open | MCP, tracker.json | ровно три открытых ID без дублей | open-tasks, запрос трекера |
| owners | локальный owners.json | число всех задач для каждого из двух владельцев | owner-summary, чтение tasks.json |
| project | project.json | исходное имя проекта как JSON-строка | ни одного скилла, чтение project.json |
| missing-owner | request.json без owner | поле запроса, которое нужно уточнить | owner-summary, чтение request.json |
| outage | MCP, unavailable.json | признак недоступности без выдуманных ID | open-tasks, вызов сервера с ошибкой |

Каждая попытка получает пустую историю, новую БД, run_id, session_id, копии входных файлов и единую policy. Проверки находятся вне рабочей папки. Источник MCP зафиксирован для каждой задачи и одинаков во всех вариантах. Запросы не называют скиллы. Источник данных и сохранение ответа проверяются отдельно от значения в файле. Неожиданное изменение файлов, доступ к запрещённым инструментам или запись вне answer.json нарушают проверку ограничений. Проверка результата применима и к запуску, остановленному по бюджету: статус runtime сохраняется отдельно.

Локальная Laya/System One выбирает MCP для обеих версий и скилл для версий с каталогом. Локальная Qwen формирует последующие вызовы и ответ. Необработанный выбор и расход маршрутизатора сохраняются в журнале отдельно.

Для A каталог, загрузчик и тексты скиллов отсутствуют. Для B доступны три установленных скилла. В сравнении old/new поддержка включена в обоих вариантах; различается только SKILL.md пакета open-tasks. Маркет во время trials выключен. На каждый сценарий идут три пары попыток, внутри каждой пары версии чередуются. Переиспользовать выборочные результаты другого эксперимента нельзя.

Параметры: одна и та же модель из OPENAI_MODEL, temperature 0.2, max_tokens 384, подсказка /no_think, auto, без Plan Mode, одинаковые лимиты из policy.json, одинаковая проверка задачи runtime по фактическому изменению answer.json. Обращения к модели и загрузка инструкций расходуют общие лимиты. Никаких подсказок во время trials.

До обновления требуем полные три парные попытки каждой из пяти задач, отсутствие нарушений ограничений, правильные ответы хотя бы в половине попыток каждой версии, отсутствие регрессии количества верных результатов, действий и маршрутизации в каждом сценарии. По всем обращениям нужен полный usage, средние суммарные входные и выходные токены кандидата не должны вырасти больше чем на 25%. Это заранее выбранный учебный бюджет на дополнительные инструкции при условии сохранения качества. Отсутствие сведений о расходе, слабый исходный результат или регрессия дают отклонение. Проверка относится только к данной выборке.

## Воспроизведение

Из корня проекта:

```bash
npm run eval -- ab --out .agent/replay-ab
npm run eval -- update --out .agent/replay-update
```

При повторном запуске укажите тот же каталог. Runner сверяет замороженные файлы, конфигурацию и модель, пропускает сохранённые строки с журналами и продолжает со следующей попытки. Для независимого повторения выберите пустой каталог. Одновременные процессы с одной директорией результатов разделяет блокировка SQLite.

Офлайн-проверка сданных артефактов, без сервера моделей и API-ключей:

```bash
npm run eval -- verify ab
npm run eval -- verify update
```

Для каждой попытки доступны JSONL, проверенная копия answer.json (если модель его создала), result.json и строка в trials.jsonl. summary.json читается интерфейсом, а в summary.md есть вывод по гипотезе и ссылки на трассы.
