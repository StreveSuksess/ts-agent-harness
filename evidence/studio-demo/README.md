# Диалоги и решения оператора в веб-интерфейсе

В студии откройте «Оценка качества» → «Диалоги из материалов сдачи» и выберите пример. Архив доступен и при пустой базе локальных сессий.

Обе сессии записаны через локальный веб-интерфейс с настоящими Laya multilingual и Qwen3. Для каждой сессии в каталоге лежат исходные запросы и ответы (`session.json`), все события в порядке исполнения (`events.jsonl`), отчёт доктора (`doctor.json`) и файлы, записанные агентом. Проверку записи оператор подтвердил в режиме safe. Отдельное планирование было выключено для демонстрации согласования записи.

| Сессия | Фактический маршрут первого запроса | Файл с ID | Уточнение в том же диалоге |
|---|---|---|---|
| [explicit](explicit/session.json) | В запросе указан MCP-трекер. Laya выбрала `mcp_tracker_list`; runtime исполнил `tracker/list`. Скилл не был загружен. | [answer.json](explicit/answer.json) содержит T1 и T3. | Агент прочитал сохранённый файл и записал [2](explicit/count.txt). |
| [ambiguous](ambiguous/session.json) | Формулировка «из трекера» привела к загрузке `open-tasks`. Модель работала с локальными файлами без обращения к MCP. | [open.json](ambiguous/open.json) содержит пустой массив. По данным учебного трекера правильный массив — T1 и T3. | Из ошибочного результата агент получил [0](ambiguous/count.txt). |

Оба запуска первого запроса получили статус `completed`: в каждой сессии была подтверждена запись файла. Сравнение содержимого с фиксированными данными показало ошибку во втором сценарии. Эти интерактивные примеры иллюстрируют разницу между статусом исполнения и качеством результата; в A/B-таблицу они не входят.

В инспекторе сессии раздел «События» позволяет отобрать Laya, скиллы и MCP и раскрыть аргументы и ответы. В разделе «Расход» показаны данные отдельно по моделям. Кнопка «Разобрать сессию» показывает расход доктора и данные каждого запуска.

## Отказ в записи

В отдельной чистой сессии оператор нажал «Отклонить», когда агент запросил запись строки `REVIEW` в `denied.txt`. Проверка в рабочем каталоге до решения и сразу после него вернула `false` для существования файла. Runtime записал событие `decision` с `choice: reject` и передал модели `tool_result` с `ok: false`.
