# Проверка качества локального агента

## Влияние скиллов

В 15 попытках без скиллов программные проверки приняли 9 файлов. При включённом каталоге — 6 из 15. Суммарный расход двух локальных моделей по данным API вырос со 136 550 до 173 614 токенов, на 27,1%. Все 30 попыток имеют полный usage. На двух целевых сценариях обе версии получили по 6 правильных файлов из 6. Гипотеза об улучшении качества на этой выборке не подтвердилась. [Протокол до измерений](ab/snapshot/PROTOCOL.md) · [Сравнение по сценариям и журналы](ab/summary.md)

- **Недоступный трекер.** В A1 Laya выбрала MCP, сервер сообщил об ошибке, и генератор сохранил требуемый признак недоступности. В B1 Laya также выбрала скилл open-tasks. В этой попытке агент пять раз получил ошибку MCP и исчерпал бюджет без файла ответа. Такая последовательность объясняет различие именно в этой паре. [A1](ab/trials/outage-A1/events.jsonl) · [B1](ab/trials/outage-B1/events.jsonl) · [Находка доктора с ID пяти событий](doctor-outage.json)
- **Контрольная задача.** Laya в варианте B правильно оставила выбор скилла и MCP пустым. В проекте сохранился JSON-объект с полем display_name, хотя запрос требовал JSON-строку. Runtime подтвердил факт записи, внешний проверяющий скрипт отклонил значение. [Ответ агента](ab/trials/project-B1/answer.json) · [Условия и результат проверки](ab/trials/project-B1/result.json)
- **Подсчёт по владельцам.** В B все три файла содержали правильные числа, хотя маршрутизатор выбирал open-tasks вместо owner-summary. В A3 файл оказался правильным при итоговом статусе failed, поскольку модель вернула текст до подтверждения задачи через complete_task. Эти случаи показывают, зачем отдельно измеряются результат, выбор скилла и статус исполнения. [Маршрут B1](ab/trials/owners-B1/result.json) · [Диагноз для A3](doctor.json)

Файлы и JSONL доступны для проверки без LLM. В корне репозитория выполните `npm run eval -- verify ab`. Для нового эксперимента используйте отдельный каталог, например `npm run eval -- ab --out .agent/replay-ab`.

Обе конфигурации внутри каждой серии использовали один процесс агента и одинаковый комплект зависимостей. Снимки package-lock.json сохранены отдельно для двух серий. Между сериями в проект добавилась библиотека yaml для чтения SKILL.md. Хеши самих скиллов сохранены в каталогах событий и в манифестах.

## Обновление open-tasks

Маркет обнаружил версию 2.0.0 и сравнил её с установленной на том же наборе сценариев. Обе версии дали по 6 правильных файлов из 15 при заранее заданном минимуме 8. В сценарии с отсутствующим полем owner рабочий процесс выполнил требуемые действия в 2 из 3 попыток со старой версией и в 1 из 3 с кандидатом. Выбор скилла совпал с ожидаемым в 12 из 15 попыток для каждой версии. Токены выросли со 171 116 до 172 237 (+0,66%). [Протокол принятия решения](update/snapshot/PROTOCOL.md) · [Итоги и все 30 журналов](update/summary.md)

Маркет отклонил обновление. После проверки осталась активна версия 1.0.0 с исходным SHA-256 `91d4ae…`. В журнале доступны полный хеш кандидата `188009…`, причина решения и обе версии пакета. Для независимого пересчёта выполните `npm run eval -- verify update`. [Журнал маркета и установленные версии](update/market-review.json)

Локальные веса Laya обеих сохранённых серий проверены отдельно по SHA-256. При новом запуске поставляемый сервер возвращает хеш фактически загруженного файла по `GET /harness/checkpoint`. Для стороннего сервера без этого метода можно указать каталог весов через `LAYA_MULTILINGUAL_MODEL_PATH` в окружении eval. Если файл и ответ сервера недоступны, манифест сохраняет `null`.
