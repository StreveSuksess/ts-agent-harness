# Как читать исходники

Начните с `runtime.ts`: это публичный фасад запуска. Затем откройте
`runtime/agent-loop.ts`, чтобы увидеть основной сценарий без деталей исполнения
инструментов, восстановления и SQLite.

## Основной путь

```text
cli.ts → cli/commands.ts → Runtime
                            ├─ start → create-run.ts
                            └─ run   → agent-loop.ts
                                         ├─ Model.complete(messages, definitions)
                                         ├─ tool-batch.ts: принять пачку вызовов
                                         └─ call-execution.ts: выполнить один вызов
                                              ├─ Policy: аргументы и разрешения
                                              ├─ call-attempts.ts: сохранить started
                                              ├─ tools.ts / administrative-tools.ts
                                              └─ call-attempts.ts: сохранить результат
```

Модель предлагает вызовы. Runtime проверяет разрешения, бюджеты и состояние,
исполняет инструменты последовательно и добавляет результаты в историю сообщений.
Полное состояние запуска сохраняется через `Store`.

## Как устроен терминал

Команда `./agent "Исправь расчёт заказа"` передаёт задачу в `cli.ts`.
`cli/arguments.ts` разбирает текст, имя команды и флаги, а `cli/commands.ts`
выбирает операцию. Для `run` модуль `cli/start.ts` по умолчанию создаёт отдельную
копию учебного workspace. Путь из `--workspace` передаётся в runtime напрямую.

- После успешного коммита `Store` вызывает обработчик `onSaved`. Модуль
  `cli/output.ts` отслеживает уже показанные сообщения. `cli/trace.ts` отображает
  новые предложения модели и отдельно соответствующие им результаты. Команда
  `trace` использует тот же формат для просмотра сохранённого разговора.
- На `awaiting_plan` и `awaiting_action` модуль `cli/presentation.ts` готовит
  план или операцию для просмотра. `cli/dialog.ts` читает ответ в терминале.
  `cli/session.ts` передаёт решение в `Runtime.approvePlan` или
  `Runtime.approveAction` вместе с ревизией показанного состояния. Если
  пользователь нажал Enter, запуск остаётся в SQLite с ожидающим решением.
- Для `runs` хранилище отдаёт короткие записи с датой, ID, статусом, папкой и
  запросом. `cli/history.ts` находит последний созданный запуск или разрешает
  введённое начало ID. Команды просмотра читают базу без обращения к модели.

## Где искать конкретную ответственность

| Модуль                            | Ответственность                                                                   |
| --------------------------------- | --------------------------------------------------------------------------------- |
| `runtime.ts`                      | Стабильный публичный API: запуск, подтверждения, восстановление, diff и откат     |
| `runtime/context.ts`              | Явные зависимости runtime: хранилище, модель и опции; загрузка policy и остановка |
| `runtime/create-run.ts`           | Начальное состояние, бюджеты и сообщения модели                                   |
| `runtime/prompts.ts`              | Системный промпт                                                                  |
| `runtime/agent-loop.ts`           | Цикл запросов к модели и обработка очереди                                        |
| `runtime/tool-batch.ts`           | Идентичность вызовов, проверка и резервирование бюджета пачки                     |
| `runtime/call-execution.ts`       | Порядок проверок, подтверждение действия и выполнение одного вызова               |
| `runtime/call-attempts.ts`        | Границы сохранения до и после исполнения                                          |
| `runtime/tool-results.ts`         | Доставка ошибок и результатов, включая кешированные                               |
| `runtime/administrative-tools.ts` | `submit_plan`, `complete_task` и проверка evidence                                |
| `runtime/task-state.ts`           | Выбор следующей задачи и отображение прогресса                                    |
| `runtime/approvals.ts`            | Решения пользователя по плану и действиям                                         |
| `runtime/recovery.ts`             | Явное разрешение неопределённого результата после сбоя                            |
| `runtime/rollback.ts`             | Diff, безопасный откат и завершение прерванного отката                            |
| `runtime/change-journal.ts`       | Накопление изменений конкретного запуска                                          |
| `model.ts`                        | HTTP-клиент модели, валидация ответа и подставная модель для тестов               |
| `policy.ts`                       | Проверка путей, команд и разрешений                                               |
| `tools.ts`, `tools/`              | Файловые операции, Bash и ограничение размера результата                          |
| `store.ts`                        | SQLite, контроль ревизий и блокировка workspace                                   |
| `journal.ts`                      | Снимки дерева, сравнение и восстановление файлов                                  |
| `schemas/`                        | JSON Schema инструментов, плана и policy                                          |
| `types/`                          | Протокол модели, план и сохраняемое состояние запуска                             |
| `cli/`                            | Ввод задачи, история запусков, показ вызовов модели и диалог подтверждений        |
| `demo.ts`                         | Воспроизводимая демонстрация с реальными инструментами                            |

`schema.ts` и `types.ts` сохраняют прежние точки импорта. Внешний код работает
через `Runtime`, `Store` и интерфейс `Model`; внутренние модули runtime получают
зависимости через `RuntimeContext`. Исполнители файловых операций и Bash не
управляют жизненным циклом агента.

## Что важно сохранить при изменениях

- Пачка вызовов и её резервы сохраняются вместе до исполнения первого вызова.
- `beginAttempt` сохраняет `started` и резерв вывода **до** запуска инструмента.
- `finishAttempt` сохраняет результат, снимок, журнал, бюджеты и tool-сообщение
  одним обновлением состояния.
- После сбоя начатое действие становится `uncertain`. Повтор требует явного
  решения пользователя; потраченный резерв автоматически не возвращается.
- Перед откатом проверяются все конфликты. Прерванный откат завершается отдельно.

Эти правила проверяются сценариями в `tests/`. Форматирование:
`npm run format`; проверка в CI: `npm run format:check`.

## Путь запроса в трекере

Обычный запуск `./agent` ведёт из `studio/cli.ts` в тот же `studio/api.ts`, который вызывает браузер через `web/transport.ts`. За сессии, общий workspace последовательных реплик и запуск runtime отвечает `studio/sessions.ts`. Код первой задачи с Python-примером доступен через `./agent run`.

- `extensions/index.ts` собирает снимок скиллов и список инструментов доверенных MCP-серверов. `studio/laya.ts` строит вопросы с конечным набором имён и обращается к локальной Laya.
- `runtime/model-turn.ts` сохраняет решение Laya и передаёт выбранные вызовы в обычную очередь. `runtime/extension-tools.ts` ограничивает доступ генератора выбранными именами. `extensions/mcp.ts` доставляет разрешённый вызов серверу.
- `studio/events.ts`, `stats.ts` и `doctor.ts` связывают запрос, наблюдаемые действия и диагноз событиями одного run. `evals/trial.ts` отдельно проверяет конечный файл и действия, даже если runtime считает запуск завершённым.
- `extensions/market.ts` отвечает за установку и закреплённые версии. `market-review.ts` применяет решение сравнения кандидата, а `evals/gate.ts` вычисляет решение по сохранённым попыткам.
